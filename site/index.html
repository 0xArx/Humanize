Give an agent everything a person has.

The problem

Agents fail at boring things.

  1. 01 It cannot receive a verification email.
  2. 02 It cannot pass an SMS code.
  3. 03 It cannot pay for the thing it needs.
  4. 04 It cannot remember yesterday.
  5. 05 It cannot survive the laptop dying.

Humanize closes each of those gaps, one layer at a time, and keeps the result in a single file so the agent always knows what it owns.

What it is

A skill, some local tools, and a window.

The skill

A short router, SKILL.md, and 24 layer guides. Any agent that can read markdown and run a shell can follow it: Claude Code, Codex, Cursor and others. It tells the agent how to work each turn, which provider to prefer, and exactly which steps need a person.

The tools

One command, humanize.py. It creates the identity, draws the avatar, starts the dashboard, and gives the agent safe helpers to read and write what it owns, remember things, and back itself up. Standard-library Python, nothing to install.

The dashboard

A full-page app on your own machine. See every layer, switch any of them off, edit the name, persona and rules, ask for changes, and jump back into the chat. It makes no third-party requests and hides secrets from the browser.

One file holds the whole agent.

Everything the agent owns lives in ~/.humanize/identity.json, readable only by you. It records what exists, so nothing is bought twice, and it holds pointers instead of secrets. The agent never edits it by hand: it uses helpers that lock the file, so the dashboard and the agent can write at the same time without losing each other's changes.

How it works

Four steps. The agent does most of them.

  1. 1

    Install

    Clone it and run one command. It creates the identity, draws the avatar, works out which app your agent chats in, and opens the dashboard. A few seconds.

  2. 2

    The agent sets itself up

    You tell it to read SKILL.md. With no one's help and no cost, it gets everything below, using its own inbox for every verification code.

    • inbox
    • phone number
    • wallet
    • DID
    • vault
    • calendar
    • avatar
    • voice
    • memory
    • dashboard
  3. 3

    One handoff

    Some things truly need a person: a CAPTCHA, a card's identity check, a notarised form. The agent prepares everything and sends you a single message, not a drip of questions.

    Setup so far is done. To finish I need about five minutes from you: a private repo to keep me in, and a token for it.
  4. 4

    Steer, and survive

    From then on you watch and steer from the dashboard. The agent backs itself up, encrypted, to a private repo, so a new machine and the self key bring it back exactly as it was.

The layers

Twenty-four things a person has.

Each layer is one thing a person has and an agent normally lacks, with its own short guide. Half of them need nobody at all. The other half say exactly what only a person can do, and nothing is presented as automatic when it is not.

Security

Secrets stay out of files. The dashboard does not trust anyone.

Where secrets live

  1. The Mailgent vaultPasswords, 2FA secrets, recovery codes and account tokens, encrypted at rest. It also produces one-time codes.
  2. The macOS KeychainThe few keys the agent needs to reach the vault and its services, and the self key. On Linux, the system keyring.
  3. The identity filePointers only, such as secret:email.agentmail.api_key. Safe to look at.
  4. The encrypted backupIdentity, secrets and memory sealed with AES-256 and an HMAC, so a wrong key or a tampered file is refused.

How the dashboard protects itself

Its Open chat button runs a command on your machine, so any web page you visit must not be able to press it.

  • Listens on your own machine only
  • Answers only requests addressed to itself, which defeats DNS rebinding
  • Refuses anything that came from another website
  • Needs a per-run token on every action
  • Shows its page only to a browser holding your access key
  • Accepts JSON only, size-limited and type-checked
  • Runs under a strict content security policy with no third-party requests
  • Hides secrets before they reach the browser

The agent can see and use its own keys, because that is what they are for. What all this guards against is everything around it: other software, other accounts on the machine, and keys leaking into files, screenshots and repositories. The full threat model, with its limits, ships in the repository.

Use it

Works with the agent you already use.

The installer links Humanize into Claude Code as a skill, so you can type /humanize or just ask.

SKILL.md and AGENTS.md are plain markdown. Point the agent at the folder, or paste SKILL.md into its rules file, and give it a shell.

Any model that can run shell commands works. Paste SKILL.md at the top of the conversation and it will open the layer guides it needs, one at a time.

The repository is private, so git needs to be able to read it. Ask 0xArx for access.

Questions

Things people ask.

What does "humanize" mean here?

Giving an agent the things a person has and it does not: a way to be reached, to pay, to prove who it is, to remember, and to keep existing. It is about capability and continuity, not about making an agent sound human.

Does the agent really sign up for everything itself?

For the first ten steps, yes: inbox, phone, wallet, vault, calendar, memory and the rest, with no person and no cost. For services that show a CAPTCHA or forbid automated sign-up, such as GitHub, X and Discord, it prepares everything and asks you for one batched handoff. It never pretends otherwise.

What does it cost?

The first ten steps cost nothing. The phone number has a five dollar credit and then three dollars a month. Everything paid after that, such as a card, a domain or a paid lookup, happens only when you fund it.

Where do my agent's keys go?

Not in a plain file. Passwords and account tokens go in the Mailgent vault. The few keys the agent needs to reach it go in the macOS Keychain or the Linux keyring. The identity file holds only pointers, and the backup is encrypted.

Can a website I visit control my agent?

No. The dashboard runs on your machine only, answers only requests addressed to itself, refuses anything from another site, and needs a token and your access key. The first version was open to exactly that attack, so it is now a test that must keep failing.

What if I lose the self key?

The backup cannot be recovered, by design. The key is shown once when the backup is created, and saved in your Keychain so pushes run unattended. Keep a copy somewhere safe.

Which platforms does it run on?

macOS and Linux, with Python 3.9 or newer. On Windows, use WSL. It has no Python packages to install.

Does it phone home?

No. The dashboard makes no third-party requests, the fonts are bundled, and nothing is sent anywhere except to the services the agent signs up for, on your behalf.
